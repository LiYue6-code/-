## 3. 状态机

### 3.1 岗位申请

| 字段 | 取值与流转 |
|---|---|
| `status` | 待审核 → 通过 / 未通过 |
| `interview_result` | 未安排 → 待面试 → 面试通过 / 面试未通过 |
| `hire_status` | 待定 → 已录用 / 未录用 |

合法动作（其余一律拒绝并提示原因）：

| 动作 | 前置条件 | 结果 |
|---|---|---|
| 初审通过 | `status=待审核` | `status=通过` |
| 初审不通过 | `status=待审核`，原因必填 | `status=未通过` |
| 安排面试 | `status=通过` 且面试未出结果 | `interview_result=待面试`，写入时间/地点 |
| 面试通过/未通过 | `interview_result=待面试` | `面试通过` / `面试未通过` |
| 登记录用/未录用 | 面试已出结果，且未录用 | `hire_status=已录用` / `未录用` |

### 3.2 就业上报

`待审核 → 已确认 / 已退回`；`已退回 → 待审核`（学生补正重报，`resubmit_count+1`，清空上次意见）。

实现类：`ApplicationFlow`、`EmploymentFlow`（纯逻辑、无 DB 依赖，便于单测与后续改动）。

## 5. 关键实现说明

- **审核留痕**：每次状态变更都写 `audit_log`（`from_status → to_status`、操作人、意见），学生端“查看进度”与负责人端“处理时间线”读同一份数据，不存在两套口径。
- **按钮由状态机驱动**：详情页的 `canApprove/canSchedule/canInterview/canHire...` 全部由 `ApplicationFlow.check(...)` 计算，页面不显示不合法操作，后端仍二次校验（防绕过）。
- **证明材料安全**：保存时用 UUID 重命名（不信任原始文件名）、扩展名白名单、5MB 上限；读取时校验文件名格式并确认解析路径仍在上传目录内，`../application.yml` 之类会被拒绝。
- **条件查询**：复杂筛选与聚合写在 XML（`resources/mapper/*.xml`），条件用 `<if>` 动态拼接，分页用 `LIMIT/OFFSET` + 独立 `COUNT`，不依赖 PageHelper。
- **导出**：CSV + UTF-8 BOM，Excel 双击打开中文不乱码；中文文件名走 RFC 5987 `filename*`。
